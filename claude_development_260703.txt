Sleep Dashboard 開發日誌 — 2026-07-03
====================================================================

問題：排除週末開關導致單夜戰力數值變化（不合理）
----------------------------------------------------------------
使用者反映：開關「排除週末」時，單夜戰力數值會變化，這個數值的
計算不應受週末設定影響才合理。

根因：updateSleepDebt() 內部用 excludeWeekend 勾選狀態篩選出的 7 夜
資料算 totalDebt，這個值同時餵給 updateCombatPower() 算
debtPenalty，導致單夜戰力（代表當下真實生理狀態）也跟著這個純顯示
用的圖表篩選開關變動。

第一輪修正：讓單夜與3夜加權都不受開關影響
----------------------------------------------------------------
updateSleepDebt() 新增 realTotalDebt，固定用未過濾的
RAW.summary.slice(-7) 計算，餵給 updateCombatPower()；原本受
excludeWeekend 影響的 totalDebt（負債長條圖、本週睡眠存款等純視覺
呈現）維持不變。

規格重新定義：3夜加權其實應該受開關影響
----------------------------------------------------------------
使用者事後明確重新定義規格：
- 單夜：只看最新單日資料，一律不受排除週末開關影響
- 3夜加權：看近三夜資料，受開關影響——開啟時只計算週間資料
- Optimizer：一律 query sleep 三夜加權值

（第一輪修正把兩者都改成不受影響是我自己的誤判，這是使用者的產品
決策，不是我能自己推論出來的，之後遇到類似情境要先問清楚。）

修正 updateCombatPower(totalDebt)：
- last = RAW.summary 真正最後一夜 → 單夜用，不受開關影響
- weightedPool = excludeWE ? RAW.summary篩掉週末 : RAW.summary
- nights = weightedPool.slice(-3)、weightedDebt = weightedPool
  .slice(-7) 算 → 3夜加權用，受開關影響
- 單夜的 debtPenalty 與 3夜加權的 weightedDebtPenalty 是兩個獨立
  變數，不可共用
- combatSub 顯示文字（睡眠債扣分/三夜日期標籤）改用對應的加權
  變數，開關開啟時標註「（已排除週末）」

實測驗證（Python 模擬）：單夜=44（不受影響）；3夜加權 toggle
關=53、開=45，符合新規格預期。

全面審查排除週末開關覆蓋率
----------------------------------------------------------------
使用者要求「Sleep Dashboard 資料理論上都要因應排除週末開關而調整
呈現數據」，逐一檢查所有 render 函式：

已正確因應（無需修改）：Stat Cards、時長/效率/百分比趨勢圖、作息
規律性、睡眠負債、戰力指數、3夜加權走勢圖（刻意不受影響，趨勢圖
用途）。

找到遺漏並修正：updatePersonalBaseline()（個人歷史基準卡片）直接
用 RAW.summary 算深睡/REM 中位數，從未檢查開關。改為基準線母體
受開關影響（開啟時只算週間夜晚），「昨晚」比對點固定用真實最後
一夜（比照單夜戰力規則）。

特例確認不需修改：updateRegularity() 內建的「Social Jetlag inline
badge」刻意用未過濾的 RAW.summary——這個指標本質是比較平日 vs 週末
入睡時間中位數的差異，若排除週末篩選會讓週末樣本歸零、指標失去
意義。

順便清除的死代碼（審查過程中發現，與開關無關）：
- updateDonut()：spec v1.4 就已移除甜甜圈卡片，函式從未被呼叫
- updateSocialJetlag()：完整版社交時差面板從未被呼叫，目標 DOM
  元素（jetlagLeft/jetlagRight/jetlagAdvice）根本不存在，已被
  jetlagInline 小徽章取代

Daily Optimizer 同步處理
----------------------------------------------------------------
Optimizer 不再自己重算戰力（v2.6 平日戰力自算的 debt 公式誤加
Math.max(0,...) clamp，違反本專案「debt 不可 clamp」規則而廢止），
改為統一直接讀 sas_combat_weighted（現在已是受開關影響的 3夜加權
版本）。

規格文件更新
----------------------------------------------------------------
sleep-dashboard-spec-v1.0.md 新增 v2.0（戰力規格重新定義）、v2.1
（排除週末覆蓋率審查+死代碼清理）兩筆版本紀錄。

教訓：「這個數值該不該因應開關」不是憑感覺判斷，要看計算語意——
基準線/統計類可以篩、平日vs週末比較類篩了會失去意義、當下生理狀態
類不該篩，三種類型判斷方式不同。
